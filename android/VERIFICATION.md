## 实现调整及其影响

1. 原生 worktree 工具无法识别父目录为 Git 仓库，使用子仓库的 Git worktree 隔离开发。影响：此 worktree 不由 Codex UI 管理；如果目录使用不当，需要手动定位本地分支。
2. 根据实际 midea-lan E1 源码采用累加校验，而非计划文字中的 CRC8。影响：若选错算法，设备将拒绝报文；协议对照和实机读取已通过。
3. DeviceConfig 的 JSON 验证与配置存储一并在任务 3 实现。影响：开发任务边界调整，无运行时差别。
4. 使用真实 5 秒调度进行有界测试，未加入测试专用时钟。影响：单元套件增加约 5 秒耗时。
5. Gradle UTP 主机测试插件未在离线缓存中，改为安装相同测试 APK 并通过 adb instrumentation 运行。影响：保留测试输出，缺少 Gradle 手机测试 HTML 报告。
6. Socket 显式使用 Wi-Fi Network 的 socket factory，仅用现有网络状态权限。影响：避免移动网络默认路由；若 Wi-Fi 不可达，应用连接失败并提示原因。
7. 审核将 Wi-Fi 原因覆盖列为 Minor；因规格要求具体错误原因，将其评为 Important 并修复。影响：避免仅显示“已停止连接”而无法定位问题。
8. 旋转测试不再要求已配对且成功连接的应用始终禁用启动按钮；按钮随真实连接状态变化。模式选择不发送控制由控制规则单元测试验证。影响：测试符合真实连接行为，物理控制仍未为测试执行。
9. 审核不判断物理控制效果及其他机型协议，按已批准范围保留：当前仅支持 7600V1E0/E1/V3 subtype 3。影响：物理执行效果未验证，其他机型不能使用本应用配置导入。
10. 保留本地开发分支 feature/android-implementation，不自动合并或推送。影响：新 Android 代码暂未进入 GitHub；源码 ZIP 可独立使用。

## 1.0.2 保管显示修正

同一台设备的关闭/开启状态对照：body[5] 为 0x81/0xA1，storage 开关从 false 变为 true，body[18] 保管剩余从 0 变为 72 小时。开启时 storage_status（body[5] 的 0x40 位）仍为 false。原先统一布尔文案将当前运行标志显示为“关闭”，混淆了当前动作与保管开关。

Python 和 Android 均将 storage_status 显示改为“运行中／当前未运行／未上报”。控制页并列展示保管开关、当前动作、剩余小时，保持原始值和协议解析。未通过剩余时间或缓存推断开关。

Python 7 项测试、Android 21 项单元测试通过，新增真实状态消息的解析回归。Tk 界面绑定检查通过；当前手机已覆盖安装 versionCode 3，保管卡片实读“开启／当前未运行／72 小时”。构建与 Lint 通过（0 错误，3 个既有警告）。用户通过面板或美居切换保管，我方仅查询状态，未发送实际控制命令。此次未重跑先前的 6 项 instrumentation。
